## Notes

- **Sequencing.** Story 1 is first because 1.4 and 1.5 decide whether the feature works at all (subagent coverage, `additionalContext` on PreToolUse). If 1.4 shows plugin hooks do not fire in subagents, stop and escalate; do not continue to story 8. Story 2 (profile keys) precedes every fixture that asserts shipped defaults. Story 3 (library) precedes the hook (8) and the `embo-deliver` change (11). Within each story the test subtasks come before the implementation subtask.
- **No throwaway files.** The user's rule forbids one-off scripts. Story 1's capture uses an inline `jq` command in the git-ignored `.claude/settings.local.json` writing to the git-ignored `tmp/`, and the 1.3 skeleton is the real hook file that grows into the final one. Nothing is written outside the project directory.
- **Bash 3.2 (D-15).** `/bin/bash` on macOS is 3.2: no associative arrays, `mapfile`, `${var,,}`, `declare -n`. Alias maps are newline lists. Every suite runs under `/bin/bash`.
- **Do not use `defer` or `allow` or `updatedInput` anywhere** (D-9, D-10); 7.10 enforces it.
- **No test may assert that an obfuscated, unclassifiable commit is denied** (D-6, PRD FR-2). The row 19 heredoc form is a regression row only: parseable shapes are refused, but the design makes no guarantee for obfuscation.
- **Shipped files carry no task numbers or `tasks/` paths** (`plugin/commands/*`, README, profiles). Hook scripts, bin wrappers and tests are exempt but the shipped comments should still say what the code does in plain terms.
- **Plugin edits are picked up** by `/reload-plugins` for hooks and `bin/` wrappers; command `.md` edits on the next prompt. Check the stale cache directory if a change has no effect.
- **Verification rows.** The design's table has 40 rows, V-1..V-40 (the author corrected the ordering and the D-13 reference to V-32). This list maps by those IDs.
- **Requirements that cannot be fully verified by a test, stated rather than invented:**
  - Accepted cost (Q-9): the environment-variable override is dropped; the profile mode is the only control, so a deliberate one-off commit on a protected branch requires editing the profile and reverting it. `EMBO_ALLOW_PROTECTED_BRANCH` survives only as negative tests proving it is inert (4.10, 8.5, 11.3).
  - Hook-to-hook `updatedInput` visibility is undocumented; 4.26 and 9.4 test the decode hedge, but which text the guard really receives can only be observed in 13.3.
  - Subagent coverage is verified only by live runs 1.4 and 13.2; no fixture can answer it.
- **Out of scope here, per PRD section 6:** work-phase branch/task correspondence, server-side git hooks, forge branch protection, blocking `merge`/`pull`/`rebase`/`reset`, automatic remediation.
